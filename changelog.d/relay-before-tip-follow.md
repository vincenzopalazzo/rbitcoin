Connecting a block that leaves IBD purges that pool. Later blocks strip too, including blocks catch-up is still writing. Peer relay and the fee filter turn on when IBD ends, including while startup is still waiting out the follow headers round. High-bandwidth compact peers are chosen once the tip has left IBD, including while that peer-relay bit is still off, so the next block from a peer is selected during the index pack. The block that leaves IBD is not selected. A store fault leaves the pool unmaintained and does not advertise relay, so the next wake retries the purge. SV2 templates follow that same maintenance signal, so a relay pause does not stop them. `-blocksonly` stays quiet. A block after IBD has already ended does not start maintenance. Class A tail backfill keeps scanning creates that land during that same window, and the `getblockstats` harness waits until Esplora binds.
